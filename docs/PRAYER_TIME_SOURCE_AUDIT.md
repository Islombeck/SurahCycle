# Аудит источников времени намаза

Дата аудита: 2026-08-26.

## Решение для Узбекистана

Основной источник расписания в Sprint 4 — **Namoz-vaqti.uz**. В приложении
он подписан именно так, с пояснением «Расписание на основе официальных
источников Узбекистана». Он не называется «официальным API ОМИ».

Выбор основан на проверяемых свойствах:

- опубликована [документация JSON API](https://namoz-vaqti.uz/en/namoz-vaqtlari/olmaliq?format=docs);
- запрос поддерживает стабильный `region`, язык, период
  `YYYY-MM` и `format=json`;
- месячный ответ содержит даты, Фаджр, восход, Зухр, Аср, Магриб, Иша и
  региональную поправку;
- опубликовано [дерево областей, городов и районов](https://namoz-vaqti.uz/ru/hududlar/);
- источник пригоден для загрузки полного месяца и локального offline-кеша.

Пример проверенного публичного запроса:

`text
https://namoz-vaqti.uz/index.php?region=toshkent&lang=ru&period=2026-08&format=json
`

Provider принимает только HTTPS, HTTP 200, JSON content type и тело не больше
256 KiB; timeout — 12 секунд. Parser требует точного совпадения requested
slug, parent slug и месяца, полного числа дней, уникальных последовательных
дат и строго упорядоченных времён. Неполный или изменившийся контракт не
попадает в cache.

Namoz-vaqti.uz сам описывает расписание как основанное на официальных
источниках Узбекистана и отдельно не гарантирует абсолютную религиозную
точность. Murajaah сохраняет эту оговорку в attribution.

## Аудит регионов

Публичное дерево было снято и проверено на build-time; приложение не
сканирует HTML во время работы.

- 14 первичных административных записей;
- 209 дочерних ссылок в опубликованном дереве;
- 14 районных ссылок с неоднозначными короткими alias исключены: JSON API
  возвращает для них одноимённые города, а отдельные `-tumani` slugs не
  опубликованы;
- 195 дочерних slugs подтверждены JSON-ответами с ожидаемыми slug/parent;
- после удаления дубликатов между крупными городами, дочерними и первичными
  записями selector содержит 209 уникальных вариантов.

Stable provider slug хранится отдельно от display name. Для дочерних записей
UI показывает родителя, например `Olmazor — Toshkent shahri`.
Координаты отдельно зафиксированы только для 14 крупных городов. Они не
выдаются за данные Namoz-vaqti.uz и используются лишь при явно включённом
математическом fallback. Для остальных мест fallback выключается, пока
координаты не пройдут отдельный аудит.

## Официальный reference и сравнительные fixtures

[O‘zbekiston musulmonlari idorasi / Muslim.uz](https://muslim.uz/en/c/prayer)
рассматривается как официальный reference, но во время аудита не найдена
открытая техническая спецификация углов, сезонных правил, округления,
страховочных интервалов и региональных поправок
`Fatvo markazi taqvim mezonlari`. Поэтому Murajaah не изобретает
`UzbekistanMuslimBoardCalculationMethod` и не маркирует generic
calculation как метод ОМИ.

Контрольная дата для Ташкента:

| Reference | Фаджр | Восход | Зухр | Аср | Магриб | Иша |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Muslim.uz, 2026-08-25 | 04:17 | 05:42 | 12:25 | 17:10 | 19:12 | 20:32 |
| Namoz-vaqti.uz, 2026-08-25 | 04:17 | 05:42 | 12:25 | 17:09 | 19:11 | 20:32 |
| Sajda comparative fixture | 04:20 | 05:42 | 12:25 | 17:10 | 19:13 | 20:29 |

Одна дата служит regression fixture, а не алгоритмом. Расхождения сохраняются
как факты; код не подгоняет provider или calculated результат под sample.

Sajda используется только для сравнительного QA. Скрытые endpoints приложений
не исследуются. Islom.uz также не используется без документированного
публичного контракта. Источник данных приложения с неоднозначным названием
«Al-Quran / Islam» остаётся unresolved comparison target.

## Математический fallback

Локальный fallback реализован через
[adhan_dart 2.0.1](https://pub.dev/packages/adhan_dart), лицензия
[MIT](https://pub.dev/packages/adhan_dart/license). Он всегда показывается как
**расчёт**, а не опубликованное расписание.

Доступны только presets, реально предоставляемые библиотекой:

- Muslim World League;
- Karachi;
- Umm al-Qura;
- Egyptian;
- Türkiye;
- Dubai;
- Qatar;
- Kuwait;
- Moonsighting Committee;
- Singapore;
- North America.

Настройки отдельно хранят method, Hanafi/Shafi Asr и high-latitude rule.
Uzbekistan fallback по умолчанию — Karachi + Hanafi Asr, но это честно
называется generic calculation и не объявляется методом ОМИ.

## Privacy

Ручной регион — основной UX. GPS не нужен для запуска и не запрашивается
автоматически. Permission появляется только после явного нажатия
«Использовать моё местоположение». Background location отсутствует. Отказ
уважается без немедленного повторного запроса, после чего остаётся полный
ручной selector.
